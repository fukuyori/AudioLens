# AudioLens 仮想オーディオデバイス ドライバー

AudioLens が取り込み元とする仮想的な再生デバイスを提供するカーネルモードドライバー。Windows のサウンド設定に「AudioLens 仮想出力」として現れ、そこへ流れた音を AudioLens 本体が WASAPI ループバックで読み取る。

**状態: 中止(2026-08-04)。使用しない。**

`audiolens.sys` / `audiolens.inf` / `audiolens.cat` の生成までは成功したが、 **このドライバは使わない。** 理由は署名ではなく安全性である。

**カーネルモードのコードは失敗の代償が大きい。** ユーザーモードのバグはアプリが落ちるだけだが、カーネルモードのバグはブルースクリーン、起動不能、最悪の場合ファイルシステムの破損になる。仮想オーディオデバイスは AudioLens の中核ではなく音の入口にすぎず、そこに OS 全体を巻き込む故障モードを持ち込む価値はない。 **VB-Cable のように広く配布され Microsoft の署名を受けたドライバは、実地で桁違いの検証を経ている。** 自作より安全である。

配布できないこと(EV 証明書が取得できない、§5)も事実だが、そちらは従たる理由にすぎない。 **署名が取れたとしても、この判断は変わらない。**

したがってこのディレクトリは **開発成果の記録** であり、ビルドも実行もしない。以下の記述は中止時点のものである。VM での動作確認手順(§3.1)も、実施しないまま残している。

実利用の取り込み元は VB-Cable 等の既存の仮想オーディオデバイスとする(`docs/requirements.md` §4.2)。

### なぜインストール検証が保留なのか

開発機は **Secure Boot が有効** である。この状態では `bcdedit /set testsigning on` が「セキュア ブート ポリシーによって保護されている」として拒否される。Secure Boot を無効化すれば通るが、

- マシン全体のセキュリティ設定の変更になる
- BitLocker が回復モードに入り、再起動時に回復キーを要求される

ため、 **開発機の環境を変えない方針を採り、この経路は採らないことにした** (2026-08-03 決定)。

### 検証を再開する経路

| 経路 | 内容 | 前提 | 状態 |
|---|---|---|---|
| **A. 仮想マシン** | VMware の VM で Secure Boot を無効化し、その中でテスト署名とインストールを行う | 既存の VMware Workstation と Windows 11 の VM | ホスト側の準備完了(§3.1)。ゲスト側は未実施 |
| **B. アテステーション署名** | Microsoft の署名を受けた正規ドライバにする。Secure Boot 有効のままインストールできる | **EV** コード署名証明書と Partner Center アカウント。§5 参照 | 未着手。手持ちの証明書は OV のため要検討 |

**公式配布を目標にしている以上、いずれ B は必要になる。** A はその前の動作確認の手段である。

## 1. 出自とライセンス

Microsoft の **Simple Audio Sample** ドライバー(`github.com/microsoft/Windows-driver-samples`、`audio/simpleaudiosample`)を土台にしている。

**ライセンスは Microsoft Public License (MS-PL)** である(`LICENSE-MS-PL.txt`)。設計書に一時「MIT」と記載していたが誤りだった。MS-PL の要点:

| 条項 | 内容 |
|---|---|
| 2(A)(B) | 著作権・特許の実施許諾。派生物の作成と配布が可能 |
| 3(A) | 商標の許諾は含まない。Microsoft の名称・ロゴは使えない |
| 3(C) | **ソフトウェアの一部でも配布するなら、著作権・特許・商標・帰属の表示をすべて保持すること** |
| 3(D) | **ソース形式で配布するなら MS-PL 下で行うこと。** バイナリ形式なら MS-PL に矛盾しないライセンスでよい |

したがって:

- `driver/` 配下のソースを公開・配布する場合、その部分は MS-PL 下に置く必要がある。
- コンパイル済みの `audiolens.sys` を製品として配布することは可能で、AudioLens 本体(`src/`)を別のライセンスにすることも妨げられない。
- 各ソースファイル冒頭の Microsoft 著作権表示は削除してはならない。

### 上流からの変更点

| 変更 | 理由 |
|---|---|
| マイクアレイ(キャプチャ)エンドポイントを削除 | AudioLens は自身の出力をループバックで読む。録音デバイス一覧を汚すだけになる |
| INF を `audiolens.inx` として書き直し | ハードウェア ID・サービス名・表示名を AudioLens のものにするため |
| 出力名を `audiolens.sys` に変更 | 同上 |
| 対応 OS の下限を 10.0.19041 (Windows 10 2004) に | 要件 N-06。上流は 22000 (Windows 11) 下限だった |

`savedata.cpp` と `ToneGenerator.cpp` は上流のまま残してある。サンプルが再生内容を WAV に書き出すための機構で AudioLens には不要だが、削除は依存関係の確認が要るため、ビルドが通ってから行う。

## 2. ビルドの前提

`winget install Microsoft.WindowsWDK.10.0.26100` に加えて、 **Visual Studio 側に 2 つのコンポーネントが必要** である。

- **Windows Driver Kit** — `WindowsKernelModeDriver10.0` プラットフォームツールセットを登録する。NuGet 版 WDK はヘッダーとライブラリを提供するが、ツールセットは提供しない。これが無いと `error MSB8020` で止まる。
- **C++ Spectre 緩和ライブラリ (最新 MSVC)** — ドライバプロジェクトは既定で Spectre 緩和を有効にするため、無いとリンクできない。

**管理者 PowerShell** で:

```powershell
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\setup.exe" modify `
    --installPath "C:\Program Files\Microsoft Visual Studio\18\Community" `
    --add Component.Microsoft.Windows.DriverKit `
    --add Microsoft.VisualStudio.Component.VC.Runtimes.x86.x64.Spectre `
    --quiet --norestart
```

GUI から行う場合は、Visual Studio Installer →「変更」→「個別のコンポーネント」で `Windows Driver Kit` と、検索欄に `64 latest spectre` と入れて出てくる項目を選ぶ。

## 3. 手順

```powershell
cd driver

# ビルド(NuGet 版 WDK は自動で復元される)
.\scripts\build.ps1
```

ビルドは署名しない。両プロジェクトで `<SignMode>Off</SignMode>` を指定してある。WDK の既定は `TestSign` で、初回ビルド時に `WDKTestCert <ユーザー名>,<連番>` という証明書を利用者のストアに黙って作ってしまうためである(2026-08-04 に生成されたものは削除済み)。

署名は明示的な手順として分離してある。

```powershell
# SafeNet USB トークンを挿してから
.\scripts\sign.ps1
```

`scripts\sign.ps1` は `CN=Noriaki Fukuyori` のコード署名証明書を探して使う。秘密鍵は USB トークン上にあるので、実行するとトークン自身のパスワード入力ダイアログが出る。 **無人ビルドには組み込めない** のはそのためで、署名を独立した手順にしてある理由でもある。

署名の順序には理由がある。カタログは INF が挙げる各ファイルのハッシュを持つので、`.sys` を最終的なバイト列にしてからでないと `inf2cat` を走らせられない。スクリプトは `.sys` 署名 → カタログ生成 → カタログ署名の順に行う。

ここから先は **管理者権限** が必要。

```powershell
# 1. テスト署名を有効にして再起動する
bcdedit /set testsigning on
Restart-Computer

# 2. 再起動後、ドライバを入れる
#    署名者証明書はカタログから自動的に取り出して信頼させる
.\scripts\install.ps1
```

**証明書を持っていてもテスト署名は要る。** Windows 10 1607 以降、カーネルドライバは Partner Center 由来の Microsoft 署名がないと読み込まれない。市販のコード署名証明書はその代わりにならない。ここでドライバを読み込ませているのはテスト署名であって、証明書ではない。証明書が効いているのは「発行元不明」の表示が消える点だけである。

### 3.1 VMware での検証環境

開発機は Secure Boot が有効で、これを変更しない方針(§状態)のため、検証は VM で行う。ホスト側の準備は `scripts\vm_prepare.ps1` が行う。

- スナップショット「AudioLens ドライバ検証前」を作成
- VM の `.vmx` に `uefi.secureBoot.enabled = "FALSE"` を書き込む(**ホストの Secure Boot には触れない**)
- ビルド済みパッケージを読み取り専用の共有フォルダー `AudioLensDriver` として見せる

VM に vTPM が付いていると、VMware は VM 全体の暗号化を要求し、暗号化された VM は `vmrun` がパスワードを求めるため自動化できない。検証中は vTPM を外してある。戻す手順は「VM → 設定 → オプション → アクセス コントロール → 暗号化」を先に行い、そのあと「ハードウェア → 追加 → Trusted Platform Module」。 **戻した TPM は新品** で、元の鍵は失われているため Windows Hello の PIN は再設定になる。

サウンド設定に「AudioLens 仮想出力」が現れる。これを **Windows の既定の出力デバイス** にし、AudioLens 本体の「取り込み元」に指定すると、すべてのアプリの音が AudioLens を通る。

戻すとき:

```powershell
.\scripts\uninstall.ps1 -RemoveCertificate
bcdedit /set testsigning off
Restart-Computer
```

### テスト署名について理解しておくこと

`testsigning on` の間は、

- デスクトップ右下に「テストモード」の透かしが出る。
- **署名されていないカーネルドライバの検証が緩む。** 開発機以外では有効にしないこと。
- BitLocker が有効な環境では回復キーを求められる場合がある。事前に確認しておくこと。
- Secure Boot が有効だと `bcdedit /set testsigning on` が拒否される。その場合は UEFI で一時的に無効化する必要がある。

## 5. 公式配布までの道筋

テスト署名は開発機限定であり、利用者の PC では動かない。一般配布には Microsoft の署名が要る。

### 5.0 手持ちの証明書と、EV が要る理由(2026-08-04 確認)

| 項目 | 値 |
|---|---|
| Subject | `CN=Noriaki Fukuyori, O=Noriaki Fukuyori, L=Kawasaki, S=Kanagawa, C=JP` |
| 発行者 | GoGetSSL G4 CS RSA4096 SHA256 2022 CA-1 → DigiCert Trusted Root G4 |
| 有効期間 | 2026-02-22 〜 2029-02-22 |
| 秘密鍵 | SafeNet Smart Card KSP(USB トークン)、RSA 4096 |
| 証明書ポリシー | **2.23.140.1.4.1 = OV(標準)コード署名** |

**EV ではない。** EV であればポリシー OID は `2.23.140.1.3` になる。この違いが効くのは次の点である。

| 用途 | この証明書で可能か |
|---|---|
| AudioLens 本体・インストーラーの署名 | **できる。** UAC の「発行元不明」が消え「Noriaki Fukuyori」と出る |
| SmartScreen の警告 | 消えるまでに **時間がかかる**。OV は評判の蓄積が要る。EV なら即時 |
| VM でのドライバ署名 | できる。DigiCert のルートは Windows に既に入っているので、ゲストへのルート証明書導入が不要になる |
| ドライバの一般配布(アテステーション署名) | **できない。** Partner Center のハードウェア開発者アカウント登録には EV が要る |

購入した商品名は「EV/OV コードサイニング証明書」だが、これは **同じ SKU で審査内容に応じてどちらかが発行される** という意味である。EV は登記済みの事業体にしか出せず、証明書のサブジェクトに次の 4 項目の記載が必須になる。この証明書にはいずれも無い。

| EV 必須フィールド | この証明書 | 実際の EV 証明書の例(Nmap Software LLC) |
|---|---|---|
| `serialNumber`(登記番号) | なし | `6397588` |
| `businessCategory` | なし | `Private Organization` |
| `jurisdictionState` | なし | `Delaware` |
| `jurisdictionCountry` | なし | `US` |

個人名義(`O=Noriaki Fukuyori`)で申請した結果 OV が発行されたということで、CA の誤発行ではない。再発行を求めても同じ結果になる。

### 5.0.1 代替経路の調査結果(2026-08-04)

**Azure Trusted Signing(現 Azure Artifact Signing)は、この用途には使えない。**

- Microsoft は Hardware Developer Program の登録と提出について、 **EV コード署名証明書を明示的に要求** し続けている。Trusted Signing は代替として認められていない。
- 個人開発者向けの Trusted Signing は **米国・カナダ在住者に限定** されている。法人枠も米国・カナダかつ 3 年以上の事業実績が要る。日本からは対象外。

一方で、 **EV 証明書が要るのは Partner Center への登録時だけ** である。Microsoft のドキュメントに「登録に必要なだけで、ドライバ自身への署名には使わない」と明記されている。ドライバに載る署名は Microsoft のものになる。つまり EV は「入場料」であって、継続的な署名作業には使わない。

### 5.0.4 案 B の見込み

EV Code Signing の規定では、証明書のサブジェクトは `Private Organization` / `Government Entity` / `Business Entity` / `Non-Commercial Entity` のいずれかでなければならない。このうち **`Business Entity` は法人格のない事業体も含む** ため、理屈のうえでは個人事業主にも道がある。

ただし規定は「登録機関(Registration Agency)による確認」を要求しており、日本では法務局の登記が想定される。 **税務署への開業届がこれに当たるとみなす CA は、実務上ほとんど無いと思われる。** 期待値は低い。

それでもメール 1 通で済み、通れば A の年 12 万円がまるごと不要になる。 **問い合わせ先は GoGetSSL(現在の証明書の発行元)のほか、SSL.com や Sectigo など複数に同時に出すとよい。** CA によって運用の幅がある。

### 5.0.5 案 E: ドライバを使わない経路 ― 実測で否定(2026-08-04)

Windows 10 2004 以降には、 **特定プロセス(とその子孫)を含む/除外して** 再生音を取り込む API がある。`ActivateAudioInterfaceAsync` に `AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK` を渡し、`PROCESS_LOOPBACK_MODE_EXCLUDE_TARGET_PROCESS_TREE` で自分自身を除外すれば、「AudioLens 以外の全アプリの音」を仮想デバイスなしで取り込める。

ただし **取り込んでも元の音は鳴り続ける** ので、そのままでは原音と補正音が二重に聞こえる。成立には元の音を止める手段が要る。唯一の候補が「音量ミキサーで音源アプリを消音し、補正音だけを鳴らす」であり、これは **消音しても取り込みが生き残る** 場合にしか成立しない。

検証ツール `src/tools/procloop/` を作って測った(`audiolens_procloop`)。1 kHz -30 dBFS の音を出すプロセスを対象に、取り込みながら `ISimpleAudioVolume::SetMute` で消音を切り替える。これは音量ミキサーが使うのと同じ API である。

```
[  5.6s] RMS  -33.0 dBFS   消音=OFF
  --- 消音しました (1.5 秒の整定待ちを挟みます) ---
[  6.1s] RMS  -33.2 dBFS   消音=ON   (整定待ち)   ← 送出済みの音の残り
[  6.6s] RMS -120.0 dBFS   消音=ON   (整定待ち)
[  7.6s] RMS -120.0 dBFS   消音=ON              ← 以降ずっと完全な無音
```

**消音前 -33.0 dBFS、消音後 -120.0 dBFS(完全な無音)。案 E は成立しない。**

理由は取り込み点の位置にある。 **プロセスループバックのタップはセッション音量・消音より後ろにある。** したがって元の音を止める操作は、必ず取り込みも一緒に止めてしまう。同じ理由でセッション音量を 0 にする方法も無効で、試すまでもない。

### 5.0.6 案 E の検証で分かった実装上の注意

将来この API を別の目的で使うときのために残す。

| 事象 | 原因と対処 |
|---|---|
| `ActivateAudioInterfaceAsync` が `E_ILLEGAL_METHOD_CALL` (0x8000000E) を返す | 完了ハンドラーがフリースレッドマーシャラーを持っていない。コールバックは Media Foundation のワークキュースレッドで呼ばれるため、アパートメントをまたげるオブジェクトでなければ音声に触れる前に拒否される。`Microsoft::WRL::RuntimeClass` に `FtmBase` を混ぜる |
| `Initialize` が失敗する | バッファ長と周期は両方 0 でなければならない。疑似デバイスが自分で決めるため、具体値を要求すると失敗する |
| `GetMixFormat` が使えない | 疑似デバイスに混合形式はない。形式は交渉ではなく宣言する。実測では `float32 48000 Hz 2ch` が通った。`AUDCLNT_STREAMFLAGS_AUTOCONVERTPCM` で OS 側が変換する |
| SDK の宣言が見つからない | `NTDDI_WIN10_FE` (0x0A00000B、Build 20348) で囲まれている。プロジェクト既定の `_WIN32_WINNT=0x0A00` では `NTDDI_WIN10` になり、宣言ごと消える。対象ターゲットにだけ `NTDDI_VERSION` を上げる |

なお **Windows 10 クライアントで動くかは未確認のまま残った** (最終ビルド 19045 < 20348)。案 E が消えたことで要件 N-06 への影響もなくなったため、追わない。

**アプリ本体の署名は今の証明書でそのまま進められる。** ドライバの方針決定を待つ必要はない。

| 段階 | 内容 | 要するもの |
|---|---|---|
| 1. 組織の実在確認 | Partner Center でハードウェア開発者アカウントを作る | 法人または個人事業としての登記情報、D-U-N-S 番号 |
| 2. コード署名証明書 | EV コード署名証明書を認証局から取得 | 年額数万〜十数万円。ハードウェアトークンで届く |
| 3. アカウントの署名 | 証明書で署名した `.cab` を Partner Center に登録 | 上記 1 と 2 |
| 4. 検証 | HLK (Hardware Lab Kit) でテストを実行し、結果パッケージを作る | HLK コントローラーとテスト対象機の 2 台構成 |
| 5. 提出と署名 | HLK パッケージを提出し、Microsoft の署名を受け取る | ― |
| 6. 配布 | 署名済みドライバをインストーラーに同梱 | ― |

**アテステーション署名** という簡略経路もある。HLK テストが不要で、EV 証明書と Partner Center アカウントだけで Microsoft の署名を受けられる。ただし:

- 対応は Windows 10 以降のみ(本プロジェクトの要件 N-06 と一致するので問題ない)。
- ドライバの種類に制限がある。オーディオのカーネルドライバは対象内。

**したがって現実的な順序は、アテステーション署名を目標にすること。** 必要なのは EV 証明書と Partner Center アカウントの 2 つで、HLK 環境の構築は不要になる。

未決事項:

- **§5.0.2 の A〜D のどれを採るか。** ここが決まらないとドライバの配布形態が決まらない。 **案 E(ドライバ不要化)は実測で消えた** ので、仮想デバイスは必須である。Azure Trusted Signing も調査の結果この用途では使えない。
- A を採る場合、法人の設立時期。EV 証明書の審査に登記事項証明書が要るため、設立が先になる。
- 年額をどう負担するか。
