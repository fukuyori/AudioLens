# M2: DSP コア 実装メモ

- 版数: 0.1
- 作成日: 2026-08-03
- 対象: `src/dsp/`、`src/core/`、`src/analysis/`、`src/audiofile/`、`src/tools/process/`

M2 の目的は、DSP チェーンと 3 スライダーのマッピングを実装し、**プリセットの効果を数値で検証できる状態にする** ことである。

---

## 1. 処理チェーン

```
入力ゲイン → ハイパス → 低域シェルフ → スピーチ帯域(最大3バンド) → 高域シェルフ
           → コンプレッサー → 出力ゲイン → ルックアヘッドリミッター
```

フィルタはチャンネルごと、コンプレッサーとリミッターはチャンネルリンク(全チャンネルに同じ利得)である。リンクしないと、片側だけ大きい音が鳴ったときに音像が動いてしまう。

DSP は **キャプチャスレッド** で動く。取り込んだフレーム数をそのまま処理でき、再生スレッド側のドリフト補正(フレーム削除・複製)が DSP の内部状態に影響しないためである。

## 2. 設計上の判断

### 2.1 コンプレッサーは RMS 検出

当初ピーク検出で実装したが、正弦波を入れると波形に追従して利得が揺れ、定常状態でもメイクアップが 0.7 dB ずれた。「音量差を整える」= 知覚的な音量を揃えることなので、10 ms 窓の RMS 検出に変更した。波形の振れを抑えるのはリミッターの役割であり、役割分担が明確になった。

`makeupReferenceDb` は「この RMS レベルの素材が、入ったときと同じ音量で出てくる」ように較正される。したがってその前後の大きい部分・小さい部分がリファレンスへ向かって寄せられる。

### 2.2 リミッターはルックアヘッド + スライディング最小値

ルックアヘッド窓の中で必要利得の **最小値** を取ることで、ピークが出力に到達する時点では既に利得が下がっている。最小値は単調デックで償却 O(1) で求める。

最終段のハードクリップは保険であり、正しく動作していればここに掛かるサンプルは 0 になる。`clippedSamples()` で数えており、テストは 0 であることを検証する。**実装中、この数値が実際にバグを検出した**(§4.1)。

### 2.3 パラメータ受け渡しは seqlock

制御スレッドが `DspParameters` を公開し、オーディオスレッドがサブブロック境界で取得する。書き込み中に読んだ場合は前回値を使い続けるため、オーディオスレッドが制御スレッドを待つことはない。

### 2.4 スムージングはサブブロック単位

32 フレーム(48 kHz で 0.67 ms)ごとに制御値を目標へ近づけ、必要なら係数を再設計する。40 ms のランプが約 60 段階になるためスライダー操作でクリックが出ない。

係数の再設計は、平滑化した制御値が前回設計時から 0.01 dB / 0.1 Hz を超えて動いたときだけ行う。ランプが収束した通常状態では再設計が完全にスキップされ、常時 tan/pow を回さずに済む。

### 2.5 denormal 対策

フィルタとエンベロープの状態は無音区間で指数的に 0 へ近づき、denormal 領域に入る。x86 では denormal 演算がマイクロコード処理となり桁違いに遅く、リアルタイム期限を割る。DSP を走らせるスレッドは `ScopedNoDenormals`(`src/common/denormals.h`)を必ずスコープする。

## 3. スライダーのマッピング

プリセットは「スライダー 0 のときの値」と「100 のときの値」を持ち、その間を線形補間する(`PresetMapping`)。マッピングをデータとして持つことで、DSP に触れずにプリセットを再調整でき、将来 JSON から読み込む形にも移行できる。

| スライダー | 動かすもの |
|---|---|
| 低音 | ハイパスのカットオフ(0 で無効 〜 100 でプリセット指定値)、低域シェルフの利得 |
| 声の明瞭さ | スピーチ帯域(最大 3 バンド)の利得、高域シェルフの利得 |
| 音量差 | コンプレッサーのスレッショルドとレシオ(0 でコンプレッサー自体を無効) |

## 4. テストが検出した不具合

### 4.1 リミッターの off-by-one(重大)

遅延ラインのリング長を `ルックアヘッド + 1` にしていたため、出力サンプルがルックアヘッド窓の 1 サンプル **外** になっていた。結果、ピークを保護できずセーフティクリップが作動し、バイパス時の遅延も 1 サンプルずれていた。

リング長をルックアヘッドと同じにすることで、「窓の最も古い要素が、いま出力されるサンプル」という不変条件が成立する。この不変条件は `limiter.cpp` にコメントとして残した。

### 4.2 整数書き出しが切り捨て

WAV 書き出しと WASAPI 出力の両方で `static_cast<int16_t>(x * 32767.0f)` としており、丸めではなく切り捨てだった。最大 1 LSB の誤差が出て、全サンプルが 0 方向へ偏る。`std::lround` に変更した。

### 4.3 テスト自身の測定手法の誤り

2 件は DSP ではなくテストの問題だった。記録しておく価値があるので残す。

- **バンドパスによる EQ 測定**: 2 次バンドパスはスカートが広く、フィルタが 20 dB 切った帯域では隣接帯域からの漏れが測定値を支配する。EQ の検証は単一正弦波で行うよう変更した。
- **試験素材の音量差が大きすぎた**: EBU R128 はゲート下限(平均の 20 LU 下)より小さい短時間ブロックを捨てる。24 dB の差を持たせた素材では静かな部分がゲートで除外され、LRA が実態を反映しなくなっていた。18 dB に変更した。

なお `audiolens_process` のバンドレベル表示は、傾向を見る用途では有効なので残してある(絶対値ではなく帯域間の相対差を見る)。

# 追補: ミッド/サイドと遅いレベリング(2026-08-04)

「効果をより高める技術」の検討から、2 つの段を追加した。

## A. ミッド/サイド処理

### A.1 なぜ効くのか

映画やドラマのセリフは、ほぼ必ずセンターに定位している。ステレオ対を

```
M = (L+R)/2   ← セリフ、ボーカル
S = (L-R)/2   ← 環境音、音楽、効果音
```

に分けると、**セリフとそれ以外がかなりの精度で分離できる**。音声帯域の持ち上げを M にだけ適用すれば、同じ持ち上げが BGM を一緒に連れてくることがなくなる。L/R 両方に掛けていた従来の方式では、それが避けられなかった。

加減算だけなので追加コストは実質ゼロ、遅延もゼロ。モノラル音源では S=0 になり自動的に無効化される。

### A.2 実測(テスト 4 件)

| 検証項目 | 結果 |
|---|---|
| センター定位への持ち上げ | 指定どおり 8 dB |
| ハードパン素材への持ち上げ | 4 dB 未満(センターとの差 2 dB 以上) |
| モノラル素材へのサイド減衰 | 影響なし(差 < 1e-6) |
| 何もしない設定での再構成 | L/R 経路と一致(差 < 1e-5) |

最後の 2 つが重要で、**この段を常時有効にしても副作用がない**ことを保証している。

### A.3 サイド減衰を音楽で使わない理由

セリフではサイドを数 dB 下げるとセンターが前に出る。音楽では**ステレオイメージが潰れる**だけで、イメージは録音の一部である。音楽プリセットではサイド利得を 0 dB に固定し、ミッド/サイドは「センターだけを持ち上げる手段」としてのみ使う。

## B. 遅いレベリング(AutoGain)

コンプレッサーは 10 ms 窓で、語句内のダイナミクスには正しい時間尺度だが、**番組ごとのレベル差**には届かない。その担当としてコンプレッサーの後ろに追加した。

### B.1 3 回間違えた

この段は設計を 3 回間違えており、**そのすべてを実測が捕まえた**。記録しておく価値がある。

| 誤り | 症状 | 原因 |
|---|---|---|
| コンプレッサーの**前**に置いた | LRA 13.13 → 12.84(4 秒交替素材) | 段が生の交替を見てしまう |
| 測定窓に BS.1770 の**短時間(3 秒)**を使った | 何を遅くしても改善しない | 番組内の変動をそのまま追従。遅れの分だけ**逆位相**に効く |
| 窓が埋まる前から**動かした** | LRA 13.13 → 17.33 | 3 秒時点の「番組レベル」は、そのとき鳴っていた区間にすぎない |

3 番目が象徴的で、「起動直後 30 秒間なにもしない」ことを避けようとした結果、**知る前に動く**段になっていた。レベリングは知らないうちは動かないのが正しい。

### B.2 確定した設計

- 測定は **30 秒の K 特性平均**。番組内の変動を平均で消し、番組そのもののレベルだけを見る
- **窓が完全に埋まるまで一切動かない**
- レートは **1 分あたり 3〜6 dB**。秒ではなく分が正しい時間尺度である。0.2 dB/秒でも、30 秒平均に残る漣を追従して範囲を広げた
- 配置はコンプレッサーの**後ろ**
- ゲート(-55 LUFS)以下では保持。無音の下のヒスを持ち上げない

### B.3 実測

| 素材 | コンプのみ | 追加後 |
|---|---|---|
| A. 番組レベル一定(32 秒) | 13.13 LU | **13.13 LU** |
| B. 番組間 18 dB 差(180 秒) | 13.63 LU | **12.65 LU** |

**仕事がなければ何もせず、あるときだけ効く。**A で悪化させないことが、この段を入れてよい条件だった。

段ごとの寄与を切り分けるため、`audiolens_process` に `--no-autogain` / `--no-midside` を追加した。この切り分けが 3 回必要になった時点で、恒久的な機能にする価値があると判断した。

## C. 既存ドキュメントの数値の訂正

**§「実測結果」の映画プリセット LRA「5.26 LU」は再現しない。** 同じ素材(`--signal dynamic`、32 秒)と同じコードで測ると **13.13 LU** である。v0.1.0 のコミットを取り出して測っても同じ 13.13 LU だったので、今回の変更による劣化ではなく、**当時の測定条件が記録と異なっていた**ことになる。条件が特定できないため、5.26 は根拠不明の数値として扱い、以後は 13.13 LU を基準とする。

## D. 音楽プリセットと分類

ロック / ジャズ / クラシック / アンビエントを追加した。音楽プリセットは**やらないこと**が中心になる。声を前に出す処理はスネアも前に出し、囁きと爆発の差を詰める処理はヴァースとコーラスの差も詰める。後者は編曲そのものである。

そのため `Preset` に分類を持たせた。

```cpp
enum class PresetCategory { Speech, Music };
```

テスト `DspChain_every_preset_does_what_its_category_promises` は、この 2 つを**逆の基準**で検証する。

- 音声プリセット: 音量差を**必ず縮める**
- 音楽プリセット: 音量差を**広げない**(縮めなくてよい)

従来の「すべてのプリセットが音量差を縮める」というテストは、音声プリセットしか存在しなかった時代の前提であり、そのままでは音楽プリセットを不必要に圧縮させることになる。

実測(`--signal dynamic` 32 秒、LRA 17.99 LU):

| プリセット | 処理後 |
|---|---|
| 会話 | 14.74 LU |
| 映画 | 13.13 LU |
| 深夜 | 3.84 LU |
| ロック / ジャズ / クラシック / アンビエント | **17.99 LU**(変化なし) |

# 追補 2: ディエッサー(2026-08-04)

## E.1 なぜ要るのか

**この段は、チェーンの他の部分が作った問題を潰すために存在する。**

音声帯域の持ち上げが明瞭さを上げる手段だが、最も強く持ち上げるプリセットは 2.6 kHz に +6 dB、その上にもさらに数 dB を足している。そこは /s/ が住む帯域でもある。つまり**明瞭さを上げるプリセットは、例外なくサ行も鋭くする**。「講義」プリセットは説明文で「長時間聞いても疲れにくい」と謳っているのに、その疲れの主因を自分で作っていた。

## E.2 実装

`src/dsp/de_esser.*`。**1 つのバンドパスが検出と減算の両方を担う。**

```
banded = bandpass(input)          # 6.5 kHz 付近、Q=1
出力    = input - g * banded      # g は毎サンプル可変
```

中心周波数ではバンドパスが入力をそのまま通すので `x - g·x = (1-g)·x` となり、**フィルタを再設計せずに深さの変わるノッチが得られる**。`g = 1 - 10^(-r/20)` で r dB の減衰になる。

### 判定は絶対レベルではなく比

閾値を絶対レベルにすると、**大きい音すべてで動作し、小さい音では何もしない**段になる。これは音が耳障りかどうかとは無関係で、小さい /s/ も大きい /s/ と同じだけ鋭い。

そのため判定は**サ行帯域のエネルギー ÷ 全帯域のエネルギー**で行う。母音はこの比が低く、/s/ は高い。番組レベルが動いても比は動かない。テスト `DeEsser_judges_by_ratio_not_by_level` が、20 dB 違う同じ素材に同じ減衰量が掛かることを確認している。

## E.3 実測

母音と歯擦音を交互に並べた素材(9.6 秒)。**会話プリセットでの帯域別の変化**:

| 帯域 | 差 |
|---|---|
| 60〜400 Hz | +0.55 dB |
| 1.0 kHz | +0.31 dB |
| **2.5 kHz** | **-0.18 dB** |
| 4.0 kHz | -1.01 dB |
| **8.0 kHz** | **-1.97 dB** |

**サ行帯域だけが下がり、明瞭さの要である 2.5 kHz は素通しになっている。**低域がわずかに上がるのは、全体レベルが下がった分コンプレッサーのメイクアップが反応するためで、副作用としては無害。

プリセット別(8 kHz 帯域の変化、素材全体の平均):

| プリセット | 明瞭さ | 差 |
|---|---|---|
| 会話 | 75 | -1.97 dB |
| 講義 | 55 | -1.62 dB |
| 映画 | 55 | -0.92 dB |
| 標準 | 35 | -0.79 dB |

(この表は「古い録音」プリセットが存在した当時の測定。2026-08-05 に同プリセットは削除し、「ゲーム」に置き換えた。ゲームではディエッサーを**無効**にしている — 理由は §E.5。)

素材の 6 割は母音なので、歯擦音の区間だけを見れば減衰量はこれより大きい。**強さが明瞭さスライダーに比例している**ことが確認できる — 問題を作るスライダーと、それを潰す段が同じ値で動く。

音楽プリセットでは無効にしてある。シンバルやハイハットもこの帯域に集中しており、比による判定でも誤動作しうる。音楽では「やらないこと」が優先される。

## E.4 母音の立ち上がりについて

テストを当初サンプル単位の一致で書いたところ落ちた。**音の立ち上がりはステップであり、ステップはサ行帯域を含む全帯域にエネルギーを持つ**ため、検出器は最初の数サンプルだけ反応する。どのディエッサーもそうなる。音そのものが無傷で出てくるかが問題なので、帯域レベルでの検証に改めた(会話プリセットで 700 Hz の変化は 0.2 dB 以内)。

## E.5 ゲームプリセットではディエッサーを切った(2026-08-05)

ディエッサーは、スピーチ帯域の強調が**声**に加えた鋭さを取り除くためにある。ゲームでは同じ 6〜8 kHz にガラス、薬莢、遠くの銃声が乗っており、それらは歯擦音ではなく**方向の手がかり**である。

`dynamic` 素材で実測すると、有効時の 8 kHz はプリセット全体のゲイン(+3.36 dB)に対して **-0.67 dB**、つまり両隣の 2.5 kHz・4 kHz が +2 dB 前後なのに 8 kHz だけ下がっていた。**その上のバンド(6.5 kHz、+3.5 dB)を自分で打ち消していた**ことになる。

無効にすると 8 kHz は全体ゲイン(+4.02 dB)に対して **+0.69 dB**。差は 1.4 dB。

| | 8 kHz(生) | 全体ゲイン | 相対 |
|---|---|---|---|
| ディエッサー有効 | +2.69 dB | +3.36 dB | **-0.67 dB** |
| ディエッサー無効 | +4.71 dB | +4.02 dB | **+0.69 dB** |

組み込みプリセットでディエッサーが無効なのは、音楽 4 種とゲーム、そして素通しの標準だけである。
