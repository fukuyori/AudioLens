# AudioLens 要件定義書

- 版数: 0.1(ドラフト)
- 作成日: 2026-08-03
- 対象プラットフォーム: Windows 10 (2004 / Build 19041) 以降、Windows 11

---

## 1. プロジェクト概要

### 1.1 目的

AudioLens は、PC で再生されるあらゆる音声を、用途に合わせて「聞き取りやすく」調整するプリセット型オーディオ補助アプリである。専門的な周波数知識を持たない利用者が、プリセットの選択と少数の分かりやすいツマミ操作だけで、以下の効果を得られることを目的とする。

- 低音の濁り(こもり)の抑制
- 人の声に必要な周波数帯の強調による明瞭度向上
- 大きすぎる音・小さすぎる音の音量差の自動平準化

### 1.2 ターゲットユーザー

| ユーザー像 | 代表的な利用シーン |
|---|---|
| オンライン会議・通話の利用者 | 相手の声が聞き取りにくい会議、録音の聞き直し |
| 学習者 | 講義動画・ポッドキャストの長時間視聴 |
| 映画・動画視聴者 | セリフが小さく効果音が大きい映画の音量差解消 |
| 深夜利用者 | 家族に配慮した小音量でもセリフが聞こえる状態 |
| 聴取に不安のある利用者 | 高域の聞き取り低下などを補う日常的な補助 |

専門用語(周波数、dB、コンプレッサー等)を知らないユーザーを主対象とする。UI 上ではこれらの用語を直接露出しない。

### 1.3 スコープ外(本バージョンでは扱わない)

- マイク入力(自分の声)の加工
- 録音・ファイル書き出し機能
- macOS / Linux 対応
- 医療機器としての聴覚補助(補聴器の代替を謳わない)

## 2. 機能要件

### 2.1 音声処理(コア)

| ID | 要件 | 優先度 |
|---|---|---|
| F-01 | システムで再生される音声をリアルタイムに取り込み、DSP 処理後に実出力デバイスへ再生できる | 必須 |
| F-02 | 低音の濁りを抑える処理(ハイパスフィルタ+低域整理)を行える | 必須 |
| F-03 | 人の声の明瞭度を上げる処理(スピーチ帯域の強調)を行える | 必須 |
| F-04 | 音量差を自動的に整える処理(コンプレッション+ラウドネス平準化)を行える | 必須 |
| F-05 | 出力段で音割れを防ぐ(リミッター) | 必須 |
| F-06 | 処理のオン/オフを即時に切り替え、処理前後を比較試聴できる(A/B 比較) | 必須 |
| F-07 | サンプルレート 44.1k/48k Hz、2ch に対応する(その他レートはリサンプル) | 必須 |
| F-08 | 処理遅延はエンドツーエンドで 50 ms 以下を目標、100 ms を上限とする(動画リップシンク許容範囲) | 必須 |

### 2.2 プリセット

| ID | 要件 | 優先度 |
|---|---|---|
| F-10 | 組み込みプリセットを提供する: 「会話」「講義」「映画」「深夜」「古い録音」「標準(処理弱め)」 | 必須 |
| F-11 | プリセットはワンクリックで切り替えられ、即時に反映される | 必須 |
| F-12 | ユーザーはプリセットを元に調整した状態を独自プリセットとして名前を付けて保存できる | 必須 |
| F-13 | 独自プリセットは出力デバイス(ヘッドホン/スピーカー等)と関連付けて保存でき、デバイス切替時に自動適用できる | 高 |
| F-14 | プリセットのエクスポート/インポート(ファイル共有) | 低 |

組み込みプリセットの意図:

| プリセット | 意図 | 処理の傾向 |
|---|---|---|
| 会話 | 通話・会議の声を聞き取りやすく | 声帯域強調・強め、低域カット中、音量平準化・強め |
| 講義 | 長時間聴取で疲れにくく | 声帯域強調・中、音量平準化・中、高域刺激を抑制 |
| 映画 | セリフと効果音の音量差を縮める | 音量平準化・強め、声帯域強調・中、低域は残す |
| 深夜 | 小音量でも聞こえるダイナミクス圧縮 | 音量平準化・最強、低域カット強め(近隣配慮) |
| 古い録音 | ノイズっぽい狭帯域音源の補正 | 声帯域強調・強め、高域補整、低域整理 |
| 標準 | 常用できる軽い補正 | 全項目・弱 |

## 4. 制約・前提

### 4.1 適用範囲: 個人利用のみ / 自作ドライバは使わない(2026-08-04 決定)

**AudioLens は作者の個人利用に限定し、一般配布は行わない。また、自作のカーネルモードドライバは使用しない。**

決定は 2 つあり、理由の重さが違う。

**(1) 自作カーネルドライバを使わない ― 安全性の判断。**カーネルモードのコードは失敗の代償が大きい。ユーザーモードのバグはアプリが落ちるだけだが、カーネルモードのバグはブルースクリーン、起動不能、最悪の場合ファイルシステムの破損になる。仮想オーディオデバイスは AudioLens の中核ではなく音の入口にすぎず、そこに OS 全体を巻き込む故障モードを持ち込む価値はない。**VB-Cable のように広く使われ、Microsoft の署名を受けて配布されているドライバは、実地で桁違いの検証を経ている。**自作より安全である。

**(2) 一般配布しない ― 実現性の判断。**仮に配布するとしても、Windows 10 1607 以降、カーネルドライバは Partner Center 由来の Microsoft 署名がなければ読み込まれない。その登録には EV コード署名証明書が要り、EV は登記済みの事業体にしか発行されない。手持ちの証明書は OV であり、法人を立てれば年 12 万円程度の固定費が生じる。ドライバを使わない代替方式(プロセスループバック)も実測で否定された。経緯は `driver/README.md` §5。

**(1) が主で、(2) は従である。**署名が取れたとしても (1) の判断は変わらない。

この決定により次が対象外になる。

| 対象外になったもの | 理由 |
|---|---|
| 自作仮想デバイスドライバ(`driver/`)の使用 | 上記 (1) |
| N-07(インストーラーによるドライバ同梱) | 配布しないため |
| N-08(ドライバの署名) | 同上 |
| F-34(英語対応) | 利用者は作者のみ |

エンジン・DSP・GUI に関する要件は一切変わらない。変わったのは「音の入口を誰が作るか」と「誰の PC で動かすか」だけである。

### 4.2 音声取り込み手段

- 音声取り込みは仮想オーディオデバイス方式を採用する(選定理由は `architecture.md` 参照)。
- **仮想デバイスには VB-Cable 等の既存ドライバを使う。**個人利用は無償で認められている。M1 で「開発フェーズの割り切り」としていた構成が、そのまま最終形になる。
- 自作ドライバ(`driver/`)は開発成果の記録として残すが、ビルドも実行もしない。
- 仮想デバイスドライバの導入に管理者権限が必要となる。
- DRM 保護された一部コンテンツや排他モード(WASAPI exclusive)再生アプリは、仮想デバイス経由では音が取れない場合がある。制限事項としてユーザーに提示する。
- 開発言語は C++(C++20)。理由: WASAPI/COM とのネイティブ親和性、低遅延リアルタイム処理、ドライバ関連コードとの整合。

## 5. 成功基準(v1.0)

1. 「映画」プリセットで、セリフ音量と効果音のラウドネス差が処理前より明確に縮小する(LUFS 計測で検証)。
2. 「会話」プリセットで、音声明瞭度の主観評価が処理前より向上する(社内試聴)。
3. YouTube 再生でリップシンクの違和感がない(遅延 100 ms 以下)。
4. 8 時間連続再生でグリッチ・クラッシュ・メモリリークがない。
