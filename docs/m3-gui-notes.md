# M3: GUI 実装メモ

- 版数: 0.1
- 作成日: 2026-08-03
- 対象: `src/app/`
- 使用フレームワーク: **Qt 6 Widgets**(検証環境は Qt 6.11.1 msvc2022_64)

---

## 1. Qt を選んだ理由

`docs/architecture.md` §2.4 で Win32 自前描画 / WinUI 3 / Qt を候補として保留していたが、Qt Widgets を採用した。

| 観点 | 判断 |
|---|---|
| 開発効率 | レイアウト、トレイ常駐、JSON、標準ダイアログが揃っており、UI に割く工数を最小にできる |
| ツールチェーン整合 | msvc2022_64 キットが既存の MSVC ビルドとそのまま噛み合う(mingw キットでは既存の静的ライブラリとリンクできない) |
| 配布 | `windeployqt` で必要な DLL とプラグインを実行ファイルの隣に揃えられる |
| 将来の多言語化 | `Qt6::LinguistTools` が同梱されており、要件 F-34 の英語対応に移行しやすい |

Qt に依存するのは `src/app/` だけである。エンジン、DSP、テストは Qt なしでビルドできる(`-DAUDIOLENS_BUILD_GUI=OFF`、または Qt が見つからない環境では自動的にスキップ)。

## 2. 画面構成

要件 F-30 のとおり 1 画面に収めている。

```
プリセット      一覧(組み込み6件 + ユーザー定義)、説明、保存/削除
効果の強さ      低音 / 声の明瞭さ / 音量差 の 3 スライダー(0〜100)
動作状況        入力レベル / 出力レベル / 音量調整(圧縮量)
音の経路        取り込み元・出力先の選択、Windows 起動時に開始
フッター        開始・停止、「押している間だけ処理前の音」、状態表示
```

周波数や dB といった用語は画面に出していない。唯一の例外は状態表示の遅延(ms)と圧縮量(dB)で、これは「動作状況」であって操作項目ではない。

### A/B 比較(要件 F-06)

「押している間だけ処理前の音」は押している間だけバイパスする。押しっぱなしという操作自体が「いま聞いているのは処理前」という状態表示になるので、切り替え忘れが起きない。

バイパス中も **リミッターだけは通る**。経路と遅延が変わらないため、比較しているのが処理の効果だけになる(`DspChain_bypass_preserves_latency` で検証)。

## 3. スレッドと COM

- UI とエンジン制御はすべて GUI スレッド。エンジンは自前のオーディオスレッドを持ち、`AudioController` は開始・停止・設定と、アトミックに公開されたカウンタの読み出しだけを行う。
- メーターは 50 ms、状態表示(遅延・途切れ回数)は 500 ms ごとに更新する。
- **COM は STA で初期化する。** Qt は GUI スレッドで `OleInitialize` を呼ぶため、MTA を先に取ると失敗する。`ComApartment` にモードを渡せるようにした(オーディオスレッドは従来どおり MTA)。

## 4. 設定とプリセットの保存(要件 F-12 / N-09)

`%APPDATA%\AudioLens\`

```
settings.json      選択デバイス、最後のプリセットとスライダー位置、自動起動
presets\*.json     ユーザーが保存したプリセット
```

- 組み込みプリセットは **ディスクに書き出さない**。更新版のビルドで内容を改善できるようにするため。
- 書き込みは `QSaveFile` 経由。途中で中断されても、元のファイルが壊れた状態で残らない。
- 読み込みは寛容に作ってある。欠けている項目は既定値で補完するので、手で書いた最小限の JSON も読める(実機で検証済み)。ただし `schemaVersion` が未来の値なら読まずに拒否する。
- 壊れたプリセットが 1 件あっても、他のプリセットの読み込みは止めない。

## 5. 実装中に見つかった不具合

### 5.1 設定の保存先が二重になっていた

`QStandardPaths::AppDataLocation` は `<Roaming>/<組織名>/<アプリ名>` を返す。組織名とアプリ名の両方を "AudioLens" にしていたため `%APPDATA%\AudioLens\AudioLens\` になっていた。組織名を設定しないことで要件どおり `%APPDATA%\AudioLens\` になる(Qt は空の要素をパスから省く)。

なお `GenericDataLocation` は Windows では Roaming ではなく **`%LOCALAPPDATA%` を返す**ため、代替にならない。

### 5.2 プリセット選択が UI Automation から反映されなかった

`QListWidget::currentRowChanged` だけを監視していた。マウスとキーボードでは「現在項目」と「選択」が一緒に動くので気付かないが、UI Automation やスクリーンリーダーは **選択だけを変える**ことがある。この経路では説明もスライダーも更新されなかった。

`itemSelectionChanged` も監視し、選択行と現在行がずれたら揃えるようにした。

### 5.3 遅延表示が 0.0 ms のまま固まっていた

状態を開始・停止の遷移時にしか通知していなかったため、開始直後(リングが空でバッファ残 0)の値である 0.0 ms が表示され続けていた。500 ms ごとに再通知するようにした。

### 5.4 プリセット一覧が潰れていた

`QListWidget` の高さを指定していなかったため、周囲のレイアウトに圧縮されて 1.5 行分しか見えていなかった。行数から高さを計算し、最大 6 行ぶんを表示する。半端な行が見切れると「描画がおかしい」ように見えるので、行の整数倍に揃えている。

### 5.5 初回起動時にスライダーがプリセットの値にならなかった

保存済み設定が無いときに `AppSettings` の既定値(50/50/50)がそのまま使われていた。初回は選択中プリセット自身の値を使うようにした(`AppSettings::restored` で判別)。

## 6. 実機での検証(2026-08-03)

UI Automation でウィンドウを操作し、`PrintWindow` で画面を取得して確認した。

| 確認項目 | 結果 |
|---|---|
| 起動と描画(日本語) | 正常 |
| 初回起動のスライダー | 標準プリセットの 30/35/35 |
| プリセット切り替え(映画) | 説明とスライダーが 35/55/80 に追従 |
| デバイス一覧 | 再生デバイスを列挙、既定に印 |
| 開始 | 動作、入出力メーターが振れる |
| 遅延表示 | 28.5 ms(うち処理 2.0 ms)、更新される |
| 圧縮量メーター | -18 dBFS の信号で -7.8 dB |
| 手書き JSON プリセットの読み込み | 一覧に出現、スライダー 90/20/10、削除ボタンが有効化 |

**検証時の注意**: 画面全体のスクリーンショットではなく `PrintWindow` で対象ウィンドウだけを取得すること。画面を撮ると利用者の他のウィンドウが写り込む。

## 8. ビルドと実行

```powershell
# Qt は自動検出される(C:\Qt などから msvc2022_64 キットを探す)
.\build.ps1

# 明示指定 / GUI を作らない
.\build.ps1 -QtDir C:\Qt\6.11.1\msvc2022_64
.\build.ps1 -NoGui

.\build\release\bin\AudioLens.exe
```

`build.ps1` はビルド後に `windeployqt` を実行するので、Qt を PATH に通さなくても起動する。

コマンドライン引数:

| 引数 | 内容 |
|---|---|
| `--minimized` | ウィンドウを出さずトレイに常駐して起動(自動起動用) |
| `--verbose` | 詳細ログを stderr へ出力 |
