# M3: GUI 実装メモ

- 版数: 0.1
- 作成日: 2026-08-03
- 対象: `src/app/`
- 使用フレームワーク: **Qt 6 Widgets**(検証環境は Qt 6.11.1 msvc2022_64)

---

## 1. Qt を選んだ理由

`docs/architecture.md` §2.4 で Win32 自前描画 / WinUI 3 / Qt を候補として保留していたが、Qt Widgets を採用した。

| 観点 | 判断 |
|---|---|
| 開発効率 | レイアウト、トレイ常駐、JSON、標準ダイアログが揃っており、UI に割く工数を最小にできる |
| ツールチェーン整合 | msvc2022_64 キットが既存の MSVC ビルドとそのまま噛み合う(mingw キットでは既存の静的ライブラリとリンクできない) |
| 配布 | `windeployqt` で必要な DLL とプラグインを実行ファイルの隣に揃えられる |
| 将来の多言語化 | `Qt6::LinguistTools` が同梱されており、要件 F-34 の英語対応に移行しやすい |

Qt に依存するのは `src/app/` だけである。エンジン、DSP、テストは Qt なしでビルドできる(`-DAUDIOLENS_BUILD_GUI=OFF`、または Qt が見つからない環境では自動的にスキップ)。

## 2. 画面構成

要件 F-30 のとおり 1 画面に収めている。**3 列**である(2026-08-05 変更)。

```
┌ プリセット ──┬ 効果の強さ ────┬ 音の経路 ──────────┐
│ 一覧(組み込み │ 低音 / 声の明瞭さ │ 取り込み元・出力先の選択    │
│ 10 件 + ユーザ │ / 音量差 / 出力音量 │ この出力先の設定として覚える │
│ ー定義)、説明、│ / 左右 の 5 段    │ 動作中は既定の出力にする    │
│ 保存 / 削除   ├ ボリューム ─────┤ Windows 起動時に開始      │
│              │ 入力 / 出力レベル、 │                        │
│              │ 音量調整(圧縮量)  │                        │
├──────────┴───────────┴────────────────┤
│ 開始・停止、「押している間だけ処理前の音」、状態表示、バージョン       │
└────────────────────────────────────────┘
```

**スライダーごとの説明文は置かない**(2026-08-05)。名前で足りており、灰色の一文が 3 行並ぶと、目が毎回それを飛び越えて操作対象にたどり着くことになる。文言はツールチップに残してある。「音の経路」にあった 4 行の説明も同じ理由でツールチップへ移した。

プリセットの説明文だけは残している。これは常設の注釈ではなく**選択に応じて変わる内容**で、そのプリセットが何をするのかを伝えるものがほかにないため。

**縦一列から 3 列へ変えた理由。**プリセットが 10 件になり、出力音量とデバイス連動の設定が加わった結果、縦積みでは 1000 px を超えてノート PC の画面に収まらなくなった。横に並べれば一番高い列(プリセット一覧)の高さで済み、実測 1036 × 471 px に収まる。

列の切り方は「何を選ぶか」「どう調整し、いま何が起きているか」「音がどこを通るか」である。メーターはスライダーと同じ列に置いた。動かした結果が出るのがメーターなので、視線を横切らせずに済む。

各列の末尾には伸縮を入れてある。これがないと、短い列のグループボックスが一番高い列に合わせて引き伸ばされ、中身がまばらな箱になる。

周波数や dB といった用語は画面に出していない。唯一の例外は状態表示の遅延(ms)と圧縮量(dB)で、これは「動作状況」であって操作項目ではない。

### A/B 比較(要件 F-06)

「押している間だけ処理前の音」は押している間だけバイパスする。押しっぱなしという操作自体が「いま聞いているのは処理前」という状態表示になるので、切り替え忘れが起きない。

バイパス中も **リミッターだけは通る**。経路と遅延が変わらないため、比較しているのが処理の効果だけになる(`DspChain_bypass_preserves_latency` で検証)。

### メーターを LED バーグラフにした(2026-08-05)

グループ名は「動作状況」から**「ボリューム」**に変えた。中身は入力・出力レベルと圧縮量で、いずれも音の大きさの話である。

**20 個のランプに分け、色は目盛りに固定する。**左から緑・黄緑・黄・橙・赤。ランプの色は決して変わらない。

#### 一度、全体の色を変えて失敗した

途中で**バー全体の色をレベルで変える**実装にしたが、これは誤りだった。理由は 3 つある。

- **色と長さが同じ数字を二重に表すだけになる。**メーターが伝えるべきは「いまどのレベルか」と「天井までどれだけ余裕があるか」の 2 つ。全体を塗り替えると、どちらも長さ 1 本から読むことになり、色は情報を増やしていない。
- **慣習に反する。**ハードウェアも DAW も色はスケール上に固定する。「赤い」は「赤い領域まで届いた」という位置の話である。
- **うるさい。**音節ごとにバー全面の色が脈打つ。周辺視野は面積の大きい色変化に敏感で、長さで既に分かっていることのために視線を引っ張り続ける。

**この変更の動機自体が誤診だった。**「-20 dBFS でも全体が緑のままだ」を不具合として扱ったが、**-20 dBFS は緑で正しい**。

実際に壊れていたのは**色帯の配分**である。`positionForDb` が上端を圧縮するため、210 px のバーで:

| 帯 | 位置 | 幅 |
|---|---|---|
| 緑 | 0 → 0.855 | 180 px |
| 琥珀 | 0.855 → 0.965 | **23 px** |
| 赤 | 0.965 → 1.0 | **7 px** |

**赤が 7 px。**帯はあったが、見えるだけの面積がなかった。しかも滑らかなグラデーションなので境界もぼやけていた。

#### いまの実装

- **20 個のランプ、隙間 2 px。**隙間がないと隣り合う色が混ざって境界が消える。滑らかなグラデーションが失敗したのはそこである。
- **色は各ランプが表す dB から引く。**-60 緑 / -24 緑寄り / -15 黄緑 / -9 黄 / -4.5 橙 / 0 赤。HSV で補間する(RGB で緑と赤を混ぜると中間が濁った茶色になる)。
- **点灯はランプの中心を越えたら。**半端に薄いランプが出ない。
- **消灯側も自分の色の暗い痕跡で描く。**目盛りが常に画面にあるので、**赤の位置が届く前から分かる**。これがメーターに本来必要な機能で、埋まるまで見えなかった旧実装には無かったものである。

圧縮量メーターも同じランプ形式にしたが、**色は青 1 色**。レベルバーが赤くなるのは「余裕がない」という警告だが、圧縮量のバーが伸びるのはアプリが仕事をしているだけで、警告ではない。

実測(300 Hz を各レベルで再生):

| 入力 | 入力バー | 出力バー |
|---|---|---|
| -40 dBFS | 緑 9 個 | 緑 9 個 |
| -18 dBFS | 緑〜黄緑 | 緑 |
| -5 dBFS | 橙まで到達 | 緑どまり(圧縮 -14.5 dB) |

### 左右バランス(要件 F-24)

「効果の強さ」の最下段。-50(左端)〜0(中央)〜+50(右端)で、表示は **`L30` / `0` / `R30`**。

符号付きの数値だけではどちらが左か考えさせることになる。当初は「左 30」「中央」としていたが、**全角 1 文字は半角のほぼ 2 倍の幅**があり、この表示は上の数値と同じグリッド列を共有している — つまり**ここに出る最長の文字列が、グループ内のスライダー 5 本すべての残り幅を決める**。`L` / `R` はオーディオ機器の表記そのままで、3 分の 1 の幅で済む。列の下限を上の数値と同じ 32 px にできるようになった。

**必ず遠い側を下げる。近い側を上げることはしない。** 上げると全開の信号がフルスケールを超え、後ろにリミッターが要る。リミッターこそ素通しプリセットが避けているものなので、それでは「効果を全部オフ」と「バランスを触る」を両立できない。減衰なら決してクリップしないので、素通し経路でそのまま適用でき、遅延は 0 ms のままである(`Balance_works_on_the_passthrough_without_costing_it_its_latency` で検証)。出力音量(F-22)とまったく同じ取引である。

カーブは**振幅に対して線形**とした。出力音量の 4 乗カーブは無音まで届く必要があるから使っているが、バランスは中央から数 dB の範囲でしか使わない。線形なら 10 % で 0.9 dB、半分で 6 dB と、使う範囲に分解能が集まる。4 乗では中央付近が粗くなって役に立たない。

**表示そのものが中央へのリセットボタンである**(2026-08-05 追加)。当初は吸着だけを頼りにしていたが、それは「中央付近までドラッグすれば戻る」という、画面のどこにも書いていない操作だった。既定値のある操作には、そこへ一発で戻す手段が要る。

押す先を新しく作らず、値の表示を押せるようにした。バランスがどうなっているか確かめるために目が行く場所は元々そこであり、独立したボタンを置けば「効果の強さ」の横幅を奪う。

スライダーのダブルクリックでも戻る。ミキサーを触ったことのある人が最初に試す操作だが、画面には現れないので、こちらは 2 番目の手段である。

**枠は描かない。**ネイティブのボタンは「動詞が書かれたボタン」向けの余白を確保するため、それを付けると値の列が広がり、グループ内のスライダー 5 本すべてが 27 px 短くなった。幅を固定して詰めると、今度は文字が切れた(「左 3」)。枠をやめると両方解決する — 上の数字とまったく同じ幅・同じ位置に収まり、押せることは**ホバー時の下線**が伝える。

幅の問題は 2 段階で潰したことになる。まず枠をやめて 27 px、次に表示を `L30` にして残る 12 px。

`QLabel` にマウス処理を足すのではなく `QPushButton` のままにしてある。キーボードと支援技術にとってボタンであり続ける必要があるため(検証も UI Automation の InvokePattern で行っている)。

中央から ±2 は **0 に吸着する**。ドラッグ中に中央へ戻す助けになり、捨てている値は最大 0.2 dB で可聴域のはるか下である。

モノラル素材では何もしない。下げる相手の側がないので、唯一のチャンネルに適用すると音量が勝手に下がったようにしか聞こえない(`Balance_is_ignored_on_mono_material` で両経路を検証)。

出力デバイスごとに記憶する(F-13)。ここに入っている値のうち、デバイス依存が最も強いのがバランスである。ヘッドホンとデスクのスピーカーが同じ方向に同じだけ偏っていることはまずない。

## 3. スレッドと COM

- UI とエンジン制御はすべて GUI スレッド。エンジンは自前のオーディオスレッドを持ち、`AudioController` は開始・停止・設定と、アトミックに公開されたカウンタの読み出しだけを行う。
- メーターは 50 ms、状態表示(遅延・途切れ回数)は 500 ms ごとに更新する。
- **COM は STA で初期化する。** Qt は GUI スレッドで `OleInitialize` を呼ぶため、MTA を先に取ると失敗する。`ComApartment` にモードを渡せるようにした(オーディオスレッドは従来どおり MTA)。

## 4. 設定とプリセットの保存(要件 F-12 / N-09)

`%APPDATA%\AudioLens\`

```
settings.json      選択デバイス、最後のプリセットとスライダー位置、自動起動
presets\*.json     ユーザーが保存したプリセット
```

- 組み込みプリセットは **ディスクに書き出さない**。更新版のビルドで内容を改善できるようにするため。
- 書き込みは `QSaveFile` 経由。途中で中断されても、元のファイルが壊れた状態で残らない。
- 読み込みは寛容に作ってある。欠けている項目は既定値で補完するので、手で書いた最小限の JSON も読める(実機で検証済み)。ただし `schemaVersion` が未来の値なら読まずに拒否する。
- 壊れたプリセットが 1 件あっても、他のプリセットの読み込みは止めない。

## 5. 実装中に見つかった不具合

### 5.1 設定の保存先が二重になっていた

`QStandardPaths::AppDataLocation` は `<Roaming>/<組織名>/<アプリ名>` を返す。組織名とアプリ名の両方を "AudioLens" にしていたため `%APPDATA%\AudioLens\AudioLens\` になっていた。組織名を設定しないことで要件どおり `%APPDATA%\AudioLens\` になる(Qt は空の要素をパスから省く)。

なお `GenericDataLocation` は Windows では Roaming ではなく **`%LOCALAPPDATA%` を返す**ため、代替にならない。

### 5.2 プリセット選択が UI Automation から反映されなかった

`QListWidget::currentRowChanged` だけを監視していた。マウスとキーボードでは「現在項目」と「選択」が一緒に動くので気付かないが、UI Automation やスクリーンリーダーは **選択だけを変える**ことがある。この経路では説明もスライダーも更新されなかった。

`itemSelectionChanged` も監視し、選択行と現在行がずれたら揃えるようにした。

### 5.3 遅延表示が 0.0 ms のまま固まっていた

状態を開始・停止の遷移時にしか通知していなかったため、開始直後(リングが空でバッファ残 0)の値である 0.0 ms が表示され続けていた。500 ms ごとに再通知するようにした。

### 5.4 プリセット一覧が潰れていた

`QListWidget` の高さを指定していなかったため、周囲のレイアウトに圧縮されて 1.5 行分しか見えていなかった。行数から高さを計算し、最大 6 行ぶんを表示する。半端な行が見切れると「描画がおかしい」ように見えるので、行の整数倍に揃えている。

### 5.5 初回起動時にスライダーがプリセットの値にならなかった

保存済み設定が無いときに `AppSettings` の既定値(50/50/50)がそのまま使われていた。初回は選択中プリセット自身の値を使うようにした(`AppSettings::restored` で判別)。

### 5.6 デバイス連動プリセットの出力音量が画面にしか反映されなかった

F-24(左右バランス)の実装中に見つけた、F-13 側の不具合。

`applyDeviceProfile()` は `loading_` を立ててスライダーを設定する。これはハンドラの二重発火を防ぐためだが、`onOutputVolumeChanged()` は `loading_` のときに `settings_.outputVolume` の更新ごと省略していた。直後の `applyCurrentSettings()` は `settings_.outputVolume` を読むので、**画面には記憶した音量が出るのに、DSP には切り替え前の音量が渡っていた。**

起動時は `settings_` を先に読み込むため露見せず、動作中に出力先を切り替えたときだけ起きる。`applyDeviceProfile()` で `settings_` へ書き戻すようにした。バランスも同じ経路を通るので、同じ穴に落ちるところだった。

## 6. 実機での検証(2026-08-03)

UI Automation でウィンドウを操作し、`PrintWindow` で画面を取得して確認した。

| 確認項目 | 結果 |
|---|---|
| 起動と描画(日本語) | 正常 |
| 初回起動のスライダー | 標準プリセットの 30/35/35 |
| プリセット切り替え(映画) | 説明とスライダーが 35/55/80 に追従 |

| 開始 | 動作、入出力メーターが振れる |
| 遅延表示 | 28.5 ms(うち処理 2.0 ms)、更新される |
| 圧縮量メーター | -18 dBFS の信号で -7.8 dB |
| 手書き JSON プリセットの読み込み | 一覧に出現、スライダー 90/20/10、削除ボタンが有効化 |

**検証時の注意**: 画面全体のスクリーンショットではなく `PrintWindow` で対象ウィンドウだけを取得すること。画面を撮ると利用者の他のウィンドウが写り込む。

## 8. ビルドと実行

```powershell
# Qt は自動検出される(C:\Qt などから msvc2022_64 キットを探す)
.\scripts\build.ps1

# 明示指定 / GUI を作らない
.\scripts\build.ps1 -QtDir C:\Qt\6.11.1\msvc2022_64
.\scripts\build.ps1 -NoGui

.\build\release\bin\AudioLens.exe
```

`scripts\build.ps1` はビルド後に `windeployqt` を実行するので、Qt を PATH に通さなくても起動する。

コマンドライン引数:

| 引数 | 内容 |
|---|---|
| `--minimized` | ウィンドウを出さずトレイに常駐して起動(自動起動用) |
| `--verbose` | 詳細ログを stderr へ出力 |
